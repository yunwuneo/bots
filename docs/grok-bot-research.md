# Grok Bot 调研与 NeoBots 自用版方案

调研日期：2026-10-11。下面的产品行为来自已读取的官方页面；技术选型是本项目的实现方案，不代表 Grok Bot 的内部架构。

## 产品定位

Grok Bot 于 2026-08-11 发布，官方定义为有自己电脑、可以持续工作的 AI 同事。用户用消息交付任务，Bot 在实际网站、应用、文件和终端中完成工作。任务可以在用户关闭客户端后继续。

这次复刻的目标是这个独立 Agent 产品的个人使用体验。

## 已核实的关键行为

| 能力 | 官方产品行为 | 自用版实现方向 |
| --- | --- | --- |
| Bot 身份 | 名字、职责、描述、独立会话及长期上下文 | Bot 配置、独立会话、显式记忆 |
| 持久化电脑 | 同一用户的 Bots 共享电脑、文件、浏览器登录态和命令行凭据 | 独立执行容器，持久化工作目录与浏览器 profile |
| 多 Bot 操作 | 每个 Bot 有自己的屏幕，可并行工作 | 每 Bot 独立浏览器标签页；工具操作串行化，后续增加独立桌面 |
| 任务运行 | 异步后台执行，可以观察进度、补充指令、停止任务 | 持久化任务队列、事件流、取消、重启恢复策略 |
| 电脑操作 | 浏览器、终端、文件；用户可以接管登录等步骤 | Playwright 浏览器与工作目录工具；截图和人工交互 |
| 集成 | 优先使用 connector，未覆盖的功能通过电脑操作完成 | 统一工具接口；后续接 MCP 和 OAuth connectors |
| Bot 协作 | 私聊、群聊、异步消息、任务移交 | Bot 间任务委派及结果回传 |
| 记忆 | 保留稳定偏好、重要事实和工作摘要，动态事实仍查来源 | 持久化可查看、可修改的记忆 |
| Skills | 可复用步骤、输入、验证方式、输出及操作边界 | 共享 Markdown 指令库 |
| Routines | 定时或外部事件触发；有拥有者、时区和运行历史 | 首版固定间隔调度；后续 cron、时区日历和 webhook |
| 人工决策 | 需要时请求审批；登录、验证码等由用户接管 | 待审批任务与准确工具参数，批准或拒绝后继续 |
| 教学 | 在支持的版本里录制操作，生成待检查的 skill | 后续阶段；首版从文字指令保存 skill |

特别注意：官方所说的“每个 Bot 有电脑”在文档中进一步解释为**同一账号共享一台电脑，每个 Bot 有自己的屏幕**。Bot 的会话/记忆分开，文件和登录态共享。

## 自用版默认选型

已确认运行环境：常开的 WSL2，Windows 浏览器访问，使用现有的兼容 API 服务。使用 Python + FastAPI 提供 API 和后台执行器，SQLite 保存 Bot、消息、任务、记忆、技能、调度与审批。前端使用原生 Web 页面，减少自用部署的依赖和构建步骤。

执行电脑作为独立 Docker 服务，提供工作目录、命令执行和 Playwright Chromium。应用不挂载 Docker socket；执行服务不对宿主机公开端口。模型 URL、模型名、API Key 通过环境变量配置，使用兼容 chat-completions 和 tool-calling 的接口。

完整桌面、原生手机/桌面客户端、语音、OAuth 集成、演示学习和插件市场分阶段实现。当前阶段以一个可验证的任务闭环作为交付边界。

## 首版验收场景

1. 创建一个研究 Bot，描述其职责并保存偏好。
2. 发出任务；页面能看到排队、执行、工具调用和结果。
3. Bot 在独立执行环境中浏览网页，保存文件并附带产物。
4. 需要确认的工具操作进入审批；刷新或关闭页面不丢失待办。
5. 批准后继续同一任务，拒绝后 Bot 能收到明确拒绝结果。
6. Bot 可以把工作交给另一个 Bot；移交有记录，循环委派受限。
7. 保存可复用 skill，并为 Bot 创建定时 routine。
8. 关闭浏览器不会停止任务；服务重启不会静默丢失队列或自动重放结果不明的外部写操作。
